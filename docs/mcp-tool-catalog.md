# MCP Tool Catalog - `alarm-management` server

_Generated by `scripts/generate_tool_catalog.py` from the running server definitions and real example calls against the simulator (anchor 2026-07-01). Do not edit by hand._

**Transport:** streamable HTTP at `http://<host>:9000/mcp` (stateless, JSON responses) or stdio (`python -m alarm_mcp --transport stdio`).

## Behaviour common to all tools

| Aspect | Behaviour |
| --- | --- |
| Authentication (client -> MCP) | `Authorization: Bearer $MCP_SERVER_TOKEN` required on `/mcp` when the token is configured (401 otherwise). `/healthz` is public. |
| Authentication (MCP -> API) | The server injects `Authorization: Bearer $ALARM_API_TOKEN`. The token never appears in tool results, traces or logs (SecretStr, redacted repr). |
| Authorization | All tools are read-only (`readOnlyHint=true`, `destructiveHint=false`). `MCP_ENABLED_TOOLS` restricts the exposed set. The copilot refuses non-read-only tools without explicit user confirmation. |
| Input validation | JSON Schema from typed signatures (Pydantic): enums, ranges, id patterns `^[A-Za-z0-9][A-Za-z0-9_.:\-]{0,63}$`, list sizes; plus semantic checks (scope required, end > start, window <= 366 days). |
| Output | `structuredContent` validated against the tool `outputSchema`; every result has a `trace` object (`trace_id`, `tool`, `duration_ms`, `retries`, `api_calls[]` with method, path, params, body, status, attempt, outcome, request_id). |
| Timeouts | Per-HTTP-attempt timeout `ALARM_API_TIMEOUT_SECONDS` (default 10 s) -> `UPSTREAM_TIMEOUT`. The copilot additionally applies `MCP_TIMEOUT_SECONDS` (default 30 s) per tool call. |
| Retries | `ALARM_API_MAX_RETRIES` (default 2) with exponential backoff + jitter (honours `Retry-After`) for 429 / 502 / 503 / 504, timeouts and connection errors. 4xx are never retried. |
| Trace propagation | `_meta.trace_id`, `_meta.conversation_id`, `_meta.client_id` from the MCP request are forwarded as `trace_id`, `x-client-id`, `x-metadata-tag`, `x-request-id` headers to the API. |
| Error format | `isError=true` result whose text is `{"error": {"code", "message", "http_status", "upstream_code", "retryable", "attempts", "trace_id", "details"}}`. Codes: `INVALID_ARGUMENT`, `NOT_FOUND`, `INVALID_REQUEST`, `AUTHENTICATION_FAILED`, `RATE_LIMITED`, `UPSTREAM_UNAVAILABLE`, `UPSTREAM_TIMEOUT`, `CONNECTION_FAILED`, `UNEXPECTED_RESPONSE`. Schema violations return the Pydantic validation message. |

### search_assets

**Search assets.** Resolve a free-text asset name, tag or equipment type (e.g. 'Boiler Feed Pump 101', 'compressor') to asset identifiers. Always call this before tools that need asset_id.

### get_alarms

**Get alarms.** Retrieve alarm occurrences filtered by asset/site/unit, status (active|cleared|shelved), severity and time window. Supports pagination; set fetch_all_pages=true to follow pages up to max_pages.

- **Underlying operation:** `GET /alarms` (filters, `page`/`page_size`, `sort_by`/`sort_order`; follows `pagination.has_next`)
- **Authentication:** MCP bearer token (client) -> API bearer token injected by the server.
- **Errors:** common mapping (above). `INVALID_ARGUMENT` when no scope (asset_id/site/unit) is given or end <= start.
- **Timeout:** per-attempt API timeout + retries as above.
- **Output fields:** `alarms`, `pagination`, `trace`

**Input schema**

| Field | Type / constraints | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `asset_id` | string (pattern=^[A-Za-z0-9][A-Za-z0-9_.:\-]{0,63}$) |  | null |  |
| `site` | string (maxLength=100) |  | null |  |
| `unit` | string (maxLength=100) |  | null |  |
| `status` | `active` \| `cleared` \| `shelved` |  | null |  |
| `severity` | array of `low` \| `medium` \| `high` \| `critical` (maxItems=4) |  | null |  |
| `alarm_name` | string (maxLength=100) |  | null |  |
| `start_time` | string (format=date-time) |  | null | ISO-8601 start (inclusive). Defaults to end_time - lookback_days. |
| `end_time` | string (format=date-time) |  | null | ISO-8601 end (exclusive). Defaults to now. |
| `page` | integer (minimum=1, maximum=10000) |  | 1 |  |
| `page_size` | integer (minimum=1, maximum=200) |  | 50 |  |
| `sort_by` | `start_time` \| `severity` \| `alarm_name` \| `asset_name` \| `duration_minutes` |  | "start_time" |  |
| `sort_order` | `asc` \| `desc` |  | "desc" |  |

### calculate_kpi

**Calculate alarm KPI.** Compute an alarm-management KPI (alarm_flood_index, critical_alarm_density, operator_response_efficiency, nuisance_alarm_score). Chains the API's generate and execute steps.

- **Underlying operation:** `POST /calculation-code/generate` then `POST /calculation-code/execute` (chained)
- **Authentication:** MCP bearer token (client) -> API bearer token injected by the server.
- **Errors:** common mapping (above). `NOT_FOUND` if the generated calculation expired; `INVALID_REQUEST` for bad filters.
- **Timeout:** per-attempt API timeout + retries as above (two API calls, each with its own timeout/retry budget).
- **Output fields:** `calculation_id`, `calculation_type`, `description`, `filters`, `result`, `trace`
